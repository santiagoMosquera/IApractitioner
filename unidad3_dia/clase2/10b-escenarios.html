¿Qué métrica importa en cada situación?

El mismo porcentaje puede significar riesgos muy diferentes según el contexto.

Redes sociales: eliminar o dejar pasar

Una plataforma identifica contenido que infringe sus reglas. Su decisión automática puede eliminar publicaciones legítimas o dejar pasar contenido infractor.

Bloquear absolutamente todo

Detectaría todas las infracciones: Recall de la clase infracción puede ser 100 %, pero también elimina publicaciones inocentes y reduce muchísimo Precision si estas son la mayoría.

No bloquear absolutamente nada

No perjudica publicaciones legítimas con bloqueos equivocados, pero el Recall para infracciones es 0 %. Precision no está definida si nunca hay predicciones positivas.

¿Qué priorizar? Cuando una eliminación injusta tiene alto costo y las infracciones leves pueden pasar a revisión posterior, buscamos mayor Precision. Si aparecen amenazas graves, la prioridad de detección puede aumentar. Un F1 alto es útil para comparar un equilibrio técnico, pero no representa automáticamente el riesgo real.

Ajuste: bajar el umbral de bloqueo suele aumentar Recall, pero puede producir falsos positivos. Subirlo puede mejorar Precision, dejando pasar más infracciones.

Facturas y notas de venta: errores similares

Una empresa clasifica 100 documentos: 50 facturas y 50 notas de venta. Confundir un tipo con el otro tiene prácticamente el mismo costo administrativo y ambos grupos tienen tamaños similares.

¿Qué priorizar? Accuracy: la proporción total de documentos bien clasificados. Si un modelo acierta 96 y otro 90, el primero es preferible bajo estos supuestos.

¿Qué cambiaría la decisión? Si perder una factura ocasiona una sanción tributaria, los costos ya no son equivalentes y necesitaríamos otras métricas o un análisis explícito de errores.

Medicina: diagnóstico preliminar

Un sistema de cribado analiza 1.000 estudios médicos para identificar una enfermedad seria. Los casos positivos deben ser derivados a revisión profesional, no tratados automáticamente.

Si se escapan pacientes enfermos: priorizamos Recall de la categoría «enfermo». Una Accuracy elevada puede ocultar este problema si la enfermedad es poco frecuente.

Si el sistema ordenara intervenciones invasivas basándose solo en una alarma: las falsas alarmas también serían graves, y aumentaría la importancia de Precision y de una confirmación clínica.

Compensación: bajar el umbral suele detectar más enfermos, pero podría generar más pruebas confirmatorias innecesarias. La decisión exige considerar seguridad, prevalencia y supervisión médica.

Banco: fraude de alto costo

Un modelo marca transacciones como fraude para revisión. Un fraude no detectado puede causar una pérdida grande, mientras una alerta falsa genera costos de verificación y molestias.

Para que se escapen menos fraudes: priorizamos Recall. Para que las alertas sean más confiables: buscamos Precision. Los umbrales y el costo monetario determinan cuál combinación conviene.

Conclusión: el objetivo no es maximizar siempre un mismo número. Primero definimos a quién protege el modelo, qué error produce más daño y qué ocurre cuando cambiamos su umbral.
