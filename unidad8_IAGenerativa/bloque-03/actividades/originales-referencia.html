Unidad 8 · Bloque 01 de 6

De la IA a la IA generativa

De la predicción a la generación, con una base común: las redes neuronales

1.1. ¿Dónde encaja GenAI?

  • Inteligencia artificial (IA) — campo de la informática que desarrolla sistemas capaces de realizar tareas asociadas con la inteligencia humana, como reconocer patrones, comprender lenguaje, razonar o tomar decisiones.
  • Machine Learning (ML) — rama de la IA en la que los modelos aprenden patrones a partir de datos para realizar predicciones o tomar decisiones sin definir manualmente todas las reglas.
  • Deep Learning (DL) — rama del ML que utiliza redes neuronales con múltiples capas para aprender patrones y representaciones complejas.
  • IA generativa (GenAI) — IA que utiliza patrones aprendidos para GENERAR contenido nuevo, como texto, imágenes, audio, video o código.
Mapa de alcance: IA, ML, DL y GenAI moderna

¿Qué hace diferente a GenAI?

Mientras un modelo predictivo devuelve una categoría o estimación (por ejemplo, «cancelará / no cancelará»), y Amazon Rekognition identifica objetos o escenas en una imagen, la IA generativa puede producir contenido nuevo: redactar un correo, crear una imagen, resumir un reporte o generar código. Son capacidades diferentes: predecir, identificar y generar.

✉️Redactar un correoResponder a un cliente con tono profesional
🎨Generar una imagenCrear una ilustración a partir de una descripción
📊Analizar un reporteResumir hallazgos y redactar conclusiones
🧮Resolver matemáticasProponer y explicar pasos, que deben comprobarse
💻Generar códigoProponer funciones y pruebas
📚Apoyar el estudioExplicar un tema con ejemplos adaptados

La IA generativa puede analizar información existente y producir explicaciones nuevas. Esa capacidad no implica que sus resultados sean siempre correctos.

Caso de cancelación: ML predice si un cliente cancelará; GenAI puede redactar un mensaje para intentar retenerlo. Son tareas distintas que pueden combinarse.

2.1. Modelos especializados frente a modelos fundacionales

FOUNDATION MODEL (FM)

Un Foundation Model es un modelo de IA ampliamente preentrenado que sirve como base para múltiples tareas y aplicaciones.

Un modelo especializado se utiliza para una tarea concreta. Por ejemplo, Amazon Rekognition detecta y reconoce elementos visuales de imágenes y videos. Un modelo fundacional puede servir como base para resolver distintas tareas, según sus capacidades.

Modelo especializado y modelo fundacional
LARGE LANGUAGE MODEL (LLM)

Un LLM es un modelo de lenguaje grande: puede generar texto, resumir, analizar o producir código.

Un FM no es necesariamente un LLM, porque también existen modelos fundacionales de imagen, audio y otras modalidades.

2.4. Multimodalidad y difusión

Un modelo multimodal puede procesar o generar más de un tipo de información, por ejemplo imagen y texto. No debemos asumir que todos los modelos multimodales manejan texto, imagen, audio y video a la vez.

Multimodalidad: diferentes formas de información

Las modalidades admitidas dependen del modelo; un modelo multimodal no necesariamente maneja las cuatro.

Muchos generadores de imágenes utilizan modelos de difusión: aprenden durante su entrenamiento a revertir progresivamente un proceso de ruido.

Difusión: aprender con ruido y generar una imagen nueva

¿En qué consiste la difusión? Es una técnica de IA generativa en la que el modelo aprende a revertir la adición progresiva de ruido. Durante la generación, parte de ruido aleatorio y lo transforma paso a paso en una imagen nueva, que puede estar condicionada por una descripción de texto.

3.2. Embeddings: del ID numérico a los vectores

En el tokenizador vemos números asociados a los tokens. Son identificadores (IDs): funcionan como códigos de un catálogo. Por ejemplo, que una palabra tenga el ID 150 y otra el 151 no indica que sus significados sean parecidos.

Dos tipos de números: NO son equivalentes
1. ID de token

«gato» → 125 «perro» → 964

Códigos de ejemplo inventados. Sirven para identificar tokens, no para comparar significado.

2. Embedding del token

«gato» → [0.81, 0.77, 0.12, …]

«perro» → [0.79, 0.73, 0.16, …]

Vectores ficticios para entender cómo el modelo representa información en múltiples dimensiones.

Texto → tokenización → ID → capa de embeddings → vector numérico de muchas dimensiones

Un embedding es un vector (lista de números) aprendido por un modelo. Esos números permiten representar características útiles de los tokens o del significado de textos completos. Los vectores reales suelen tener muchas dimensiones, no solamente las dos o tres que podemos dibujar.

Una frase completa también puede representarse como vector

En una búsqueda semántica, un modelo de embeddings genera un vector para la consulta «no puedo entrar a mi cuenta» y otro para el documento «restablecer contraseña». El sistema compara ambos vectores de texto. Esto no equivale a comparar los IDs individuales de cada palabra.

Analogía: nuestro cerebro relaciona «recuperar acceso» con «restablecer contraseña» mediante experiencias. La máquina no piensa igual: calcula representaciones numéricas aprendidas y compara su similitud.

3.3. Transformer y Attention: ¿en qué momento actúan?

Transformer es una arquitectura de red neuronal. Después de tokenizar el texto, la red convierte los IDs en embeddings, incorpora información de posición y procesa las representaciones mediante varias capas que incluyen Attention y redes neuronales adicionales.

Attention calcula relaciones entre los tokens a partir de sus representaciones numéricas. No son «nuevos números asignados por el tokenizador»: son pesos de atención calculados dentro del Transformer y varían según el contexto y la capa.

¿Cuándo se calcula la atención?
Al procesar la pregunta

El Transformer relaciona tokens de la pregunta y su contexto para construir representaciones contextualizadas.

Al generar la respuesta

La red calcula el siguiente token usando el contexto anterior; los tokens nuevos también participan en cálculos de atención en los pasos siguientes.

IDs de entrada → embeddings → capas Transformer (Attention) → probabilidades → token nuevo → repetir

En los LLM autorregresivos se utiliza normalmente atención causal: al predecir el siguiente token no se observan tokens futuros.

Ejemplo: «El estudiante perdió su archivo y luego intentó recuperarlo»

La conexión entre archivo y recuperarlo ilustra qué relación contextual interesa. El peso de atención real no puede deducirse directamente de esta frase; el resaltado siguiente es pedagógico.

¿Qué pasa cuando una aplicación busca en Internet?

El LLM no convierte automáticamente toda la Web en embeddings para buscar. Una herramienta externa de búsqueda obtiene resultados o fragmentos de páginas y la aplicación los incorpora al contexto del modelo. El LLM tokeniza y procesa el texto que recibe para generar su respuesta.

En una búsqueda semántica con índice vectorial, los documentos pueden haber sido divididos y vectorizados de antemano. Cuando llega una consulta nueva se calcula su embedding y se buscan documentos cercanos. Son arquitecturas distintas, que algunas aplicaciones combinan.

Dos maneras de recuperar contenido externo
Búsqueda web
Consulta → buscador web → páginas o fragmentos → contexto del LLM

El buscador puede usar diferentes métodos; no asumimos que cada página fue tokenizada por el LLM previamente.

Índice semántico
Documentos → embeddings guardados
Consulta → su embedding → vectores cercanos → contexto del LLM

Los documentos ya indexados no necesitan recalcularse por cada consulta salvo actualizaciones.

La búsqueda y el mecanismo de Attention del Transformer son procesos diferentes: el primero recupera fuentes externas; el segundo calcula relaciones entre tokens dentro del modelo.

3.4. ¿Por qué un LLM no es simplemente Amazon Comprehend?

Amazon Comprehend ofrece operaciones especializadas de NLP, como análisis de sentimientos, entidades y frases clave. Un LLM tiene capacidades de lenguaje generales y puede generar respuestas siguiendo instrucciones; también puede clasificar o extraer información.

Un mismo comentario, dos enfoques
Amazon Comprehend

Entrada: “La cámara es excelente, pero la batería dura poco”.

Resultado: señales estructuradas como sentimiento y frases clave, según las operaciones utilizadas.

LLM generativo

Entrada: el mismo comentario + “redacta una respuesta al cliente”.

Resultado: texto nuevo: “Lamentamos el problema con la batería…”

Un LLM también puede clasificar texto; Comprehend ofrece API especializadas de NLP.

Pregunta de clase: para analizar 200.000 comentarios con un esquema fijo de sentimiento y entidades, ¿qué ventajas podría tener un servicio especializado? Comparar integración, costo y requisitos de evaluación.

3.5. Ventana de contexto

La ventana de contexto limita la cantidad de tokens que el modelo puede procesar en una operación. Instrucciones, conversación, documentos y parte de la salida pueden competir por ese presupuesto, según el modelo y servicio.

No es memoria permanente: cuando la conversación crece, la aplicación puede resumir, recortar o recuperar información de forma externa, pero no garantiza que todo lo anterior siga disponible.

Unidad 8 · Bloque 04 de 6

Por qué las respuestas pueden variar

Estocasticidad, temperatura, muestreo y costos

4.1. Determinístico y no determinístico

En un proceso determinístico, la misma entrada y las mismas condiciones dan la misma salida. Un sistema no determinístico puede producir respuestas distintas ante la misma entrada. En los LLM esto puede ocurrir cuando se seleccionan tokens entre varias alternativas probables. No significa que las respuestas siempre cambien: depende del modelo, la configuración y la forma de generación.

Determinístico

«2 + 2» → 4
«2 + 2» → 4

No determinístico

«Nombra una marca ficticia» → Nexora
«Nombra una marca ficticia» → Lumitek

Un LLM puede responder de forma diferente al mismo prompt, incluso si la pregunta no cambia. La temperatura y las estrategias de selección de tokens ayudan a explicar esa variabilidad. Una temperatura baja no garantiza que la respuesta sea correcta.

4.2. Temperatura, Top-k y Top-p

Temperatura: modifica las probabilidades. Baja favorece candidatos más probables; alta distribuye más probabilidad entre alternativas. Úsala como analogía: fría = conservadora; caliente = más espontánea. No implica mayor lógica ni verdad.

Top-k: conserva una cantidad fija de los candidatos más probables. Top-p: conserva el conjunto mínimo cuya probabilidad acumulada alcanza el umbral establecido.

4.3. Longitud, latencia, throughput y costos

Longitud

Tokens que se generan. Los límites de salida condicionan el tamaño de las respuestas.

Latencia

Tiempo para empezar o completar una respuesta, según la medida.

Throughput

Solicitudes o tokens procesados por unidad de tiempo.

Muchos servicios cobran según tokens de entrada y salida, modelo y modalidad. Un modelo más grande no es siempre la mejor elección para toda tarea.

Un asistente incluye el mismo manual de 100 páginas para responder preguntas de vacaciones, permisos y ausencias. Cuando el servicio lo permite, puede reutilizar el procesamiento de un prefijo idéntico del prompt y reducir procesamiento repetido.

4.5. Alucinaciones

Un LLM puede presentar afirmaciones plausibles pero inventadas, como una cita de un artículo científico inexistente. Temperatura baja no garantiza veracidad.

Clasificación ML

Un cliente cancela, pero el modelo predice «no cancela»: error de clasificación o falso negativo.

Respuesta generativa

Un LLM inventa un artículo y lo presenta como real: alucinación.

5.2. ¿Cómo se relacionan los términos?

Instruction Tuning es una forma de fine-tuning con pares de instrucciones y respuestas. Por ejemplo: «Resume el contrato en tres puntos» → tres puntos correctos.

Transfer Learning es la estrategia general de aprovechar aprendizaje previo; hacer fine-tuning sobre un modelo preentrenado es un caso de transferencia.

RLHF utiliza comparaciones de respuestas y preferencias humanas como señal para optimizar comportamientos. En el enfoque clásico se entrena un modelo de recompensa y después se emplea aprendizaje por refuerzo.

Distillation utiliza un modelo profesor para enseñar a un estudiante; permite desarrollar una versión más compacta o eficiente, aunque no conserva siempre todas las capacidades.
